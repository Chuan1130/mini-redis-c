# archive 目录说明

这个目录用于保存“已经完成历史使命，但又值得保留用于学习对照”的旧实现。

## 什么时候使用 archive

当旧代码满足下面两个条件时，适合移动到这里：

1. 它已经不再是主路径实现。
2. 它继续留在 `src/` 中会明显干扰当前章节的阅读。

## 当前仓库状态

当前仓库里已经真正归档了几类旧实现：

- `archive/ch01_legacy/`

- `archive/ch03_legacy/`
  - 保存固定桶数哈希表版本，以及 ch03 实现前的旧计划文档
- `archive/ch04_legacy/`

  - 保存 ch05 实现前的旧计划文档

  - 保存 ch06 实现前的旧计划文档

另外，当前主线里仍然保留了一小段旧逻辑痕迹：

它规模还不大，所以现在继续原地保留，并通过注释说明它的历史作用。

## 未来建议的归档方式

如果后续确认某段旧实现已经影响主线阅读，建议按章节建立目录，例如：

```text
archive/ch01_legacy/
archive/ch02_legacy/
```

每个 legacy 文件顶部都应写清楚：

- 它属于哪一章或哪个阶段
- 当时解决了什么问题
- 为什么后来被替换
- 新实现现在在哪个文件
